# Cardiovascular Disease Risk Prediction

> AI Generated Documentation
>
> This documentation was generated by AI through static analysis of the project's source code. It represents the implementation at the time it was generated and may become outdated as the code evolves. Always treat the source code as the ultimate source of truth.

A full-stack web application for predicting cardiovascular disease risk using a Logistic Regression machine learning model. Users input 12 biometric parameters through a cyber-themed React frontend. The Flask backend runs inference using a pre-trained model and returns a risk probability, severity category, and personalized health recommendations.

---

## Purpose

This project applies supervised machine learning to the Kaggle Cardiovascular Disease dataset to provide an accessible, real-time risk assessment tool. It is intended for:

- Educational demonstration of end-to-end ML deployment (training through web inference)
- Developers learning how to serve a scikit-learn model behind a REST API
- Anyone interested in a worked example of a Logistic Regression pipeline with a React frontend

**Disclaimer** (from the application footer): *This system provides AI-based risk analysis. Not intended for medical diagnosis.*

## Features

- **Biometric Data Input** — Form with 12 parameters organized into sections: Demographics, Physical Metrics, Blood Pressure, and Health & Lifestyle
- **Real-time BMI Calculation** — Height and weight inputs automatically compute BMI with categorical classification
- **ML-backed Risk Prediction** — Logistic Regression model produces a probability score
- **Risk Categorization** — Four-tier severity: Low, Moderate, High, Very High
- **Personalized Recommendations** — Rule-based advice generated from input values and prediction probability
- **REST API** — Three endpoints: health check, prediction, feature metadata
- **Dark Cyber UI** — MUI-based theme with neon glow effects, scan-line animation, glassmorphism cards, and grid background
- **Mobile-Responsive Layout** — Two-column layout on large screens; stacks on small screens
- **Error Handling** — Graceful fallbacks for missing model files, invalid input, or server errors

## Architecture

### High-Level Design

The application follows a two-tier client-server architecture:

```
┌──────────────────────┐       HTTP/JSON        ┌──────────────────────┐
│   React Frontend     │ ◄──────────────────────►│   Flask Backend      │
│   (Create React App) │     POST /predict       │   (Gunicorn + Render)│
│                      │     GET /health          │                      │
│   Port 3000 (dev)    │     GET /features        │   Port 5000 / :443   │
└──────────────────────┘                         └──────────┬───────────┘
                                                            │
                                                            ▼
                                                  ┌──────────────────┐
                                                  │  model.pkl       │
                                                  │  scaler.pkl      │
                                                  │  features.pkl    │
                                                  └──────────────────┘
```

### Request Flow

1. User fills out 12 biometric fields in the React form (`PredictionForm.js`)
2. On submit, `App.js` inverts the `smoke` and `alco` values (0 ↔ 1) before sending — this is a client-side workaround for a label encoding mismatch between the form UI and the training data
3. A `POST` request is sent to `{REACT_APP_API_URL}/predict` with a JSON body containing all 12 feature values
4. Flask's `app.py` receives the JSON, extracts features in the exact order from `features.pkl`, handles missing fields with default fallbacks, scales the input via `scaler.transform()`, and calls `model.predict_proba()`
5. The response JSON includes: `probability` (0–100), `risk_category`, `prediction` (High/Low Risk), `recommendations` (list of strings), `features_used`, and `features_values`
6. The frontend renders the probability as a percentage inside a color-coded square, shows the risk category, and lists system recommendations

### Data Flow (Training Pipeline)

```
cardio_train.csv
    │
    ▼
model_training.py
    ├── Load CSV (semicolon delimiter, 70,000 rows)
    ├── Remove outliers (ap_hi 90–200, ap_lo 60–120, weight 30–200, height 100–250)
    ├── Feature engineering
    │     ├── age_days → age_years (÷365.25)
    │     └── height + weight → bmi (weight / (height/100)²)
    ├── Drop columns: id, age (original days), cardio (moved to y)
    ├── Train/Test split (80/20, stratified by target)
    ├── StandardScaler fit_transform on training set
    ├── LogisticRegression training (class_weight='balanced', solver='liblinear', max_iter=1000)
    ├── Evaluation (accuracy, ROC AUC, classification report)
    └── Save model.pkl, scaler.pkl, features.pkl
```

### State Management

- **Frontend**: Local React state via `useState` in `App.js` (`result`, `loading`, `error`) and `PredictionForm.js` (`formData`, `bmi`)
- **Backend**: Stateless; model artifacts loaded once at import time

### Error Handling Strategy

| Layer | Strategy |
|-------|----------|
| Backend — model load | Caught by `try/except`; `model`, `scaler`, `feature_names` set to `None`/`[]`; `/predict` returns 500 with `'Model not loaded'` |
| Backend — prediction | Caught by `try/except`; returns 400 with `{'success': False, 'error': str(e)}` |
| Backend — missing input | Checks `request.get_json()`; returns 400 with `'No input data provided'` |
| Backend — missing features | Falls back to defaults: `age_years` (50), `bmi` (computed from height/weight), or `0.0` |
| Frontend — network | `catch` block sets error state to generic "Something Went Wrong" message |
| Frontend — API error | Checks `data.success`; if falsy, displays `data.error` |
| Frontend — no model | Health endpoint returns `model_loaded: false` |

## Core Components

### Backend: `app.py`

**Responsibility**: HTTP API server for risk prediction.

- **`GET /`** — Returns API metadata (message, status, available endpoints)
- **`GET /health`** — Returns `{"status": "healthy", "model_loaded": true/false}`
- **`POST /predict`** — Accepts JSON with 12 biometric features; returns prediction probability, risk category, and health recommendations
- **`GET /features`** — Returns expected feature names, descriptions, and an example input object
- **`get_risk_category(probability)`** — Thresholds: <0.3 → Low, <0.6 → Moderate, <0.8 → High, ≥0.8 → Very High
- **`get_recommendations(data, probability)`** — Rule-based recommendation engine, checks cholesterol, blood pressure, smoking, alcohol, physical activity, BMI, and overall risk level

**Input validation**: Missing features are handled with defaults (`age_years` → 50, `bmi` → computed or 25, others → 0).

**CORS**: Wide-open (`origins: "*"`) — allows cross-origin requests from any frontend domain.

### Backend: `model_training.py`

**Responsibility**: Offline model training and serialization.

- Loads `cardio_train.csv` (semicolon-delimited)
- Cleans extreme outliers from blood pressure, weight, and height
- Engineers `age_years` (from days) and `bmi` (from height/weight)
- Drops `id` and original `age` columns
- Trains a `LogisticRegression` with `class_weight='balanced'` to handle class imbalance
- Evaluates on a stratified 20% test set (accuracy, ROC AUC, classification report, feature coefficients)
- Saves `model.pkl`, `scaler.pkl`, `features.pkl` for the API server

### Frontend: `App.js`

**Responsibility**: Application shell; orchestrates form submission, API communication, and result rendering.

- Reads `REACT_APP_API_URL` from environment
- On submit: inverts `smoke` and `alco` values, sends `POST` to `{api}/predict`
- Renders a two-column layout: form on the left, results on the right
- Results panel shows:
  - Large risk percentage in a color-coded square with glow effect
  - Risk category label (Low/Moderate/High/Very High)
  - Status indicator with icon (CheckCircle/Warning/Error)
  - List of system recommendations
  - Risk metrics (confidence bar, severity level)
- Loading state: spinner with "PROCESSING NEURAL DATA" animation
- Empty state: arrow icon with "AWAITING INPUT DATA"

### Frontend: `PredictionForm.js`

**Responsibility**: Controlled form with 12 biometric parameter inputs.

Four visual sections:

BMI classification includes humorous edge-case labels near thresholds (e.g., "1 biscuit away from Obese").

## APIs

### `POST /predict`

**Purpose**: Submit patient biometric data and receive a cardiovascular risk prediction.

**Where it is used**: Called by `App.js:handlePrediction` when the user clicks "ANALYZE".

**Authentication**: None (public API).

**Request body** (JSON):
```json
{
  "gender": 2,
  "height": 170,
  "weight": 70,
  "ap_hi": 120,
  "ap_lo": 80,
  "cholesterol": 1,
  "gluc": 1,
  "smoke": 0,
  "alco": 0,
  "active": 1,
  "age": 50
}
```

*Note: `age` is accepted and converted to `age_years` by the backend; `height` + `weight` are used to compute `bmi` if `bmi` is not provided directly.*

**Response** (200):
```json
{
  "success": true,
  "probability": 23.45,
  "risk_category": "Low Risk",
  "prediction": "Low Risk",
  "recommendations": ["Maintain a healthy lifestyle with balanced diet and exercise."],
  "features_used": ["gender", "height", ...],
  "features_values": {"gender": 2.0, "height": 170.0, ...}
}
```

**Error responses**:
- `400` — `{"success": false, "error": "..."}` (invalid/missing input)
- `500` — `{"error": "Model not loaded"}` (model artifacts failed to load at startup)

### `GET /health`

**Purpose**: Check if the API server and model are operational.

**Response**:
```json
{"status": "healthy", "model_loaded": true}
```

### `GET /features`

**Purpose**: Retrieve the expected feature schema and an example input.

**Response**: JSON with `features` (list of 12 names), `descriptions` (map), `example_input` (sample JSON object).

### `GET /`

**Purpose**: API root with metadata and available endpoint list.

**Response**:
```json
{
  "message": "Cardiovascular Disease Prediction API",
  "status": "running",
  "endpoints": { "/predict": "POST - ...", "/health": "GET - ...", "/features": "GET - ..." }
}
```

## How It Works

1. **Model Training** (`model_training.py`): A Logistic Regression model is trained offline on the Kaggle Cardiovascular Disease dataset. The script cleans outliers, engineers features (`age_years`, `bmi`), scales with `StandardScaler`, and saves the trained model, scaler, and feature list to disk as pickle files.

2. **Server Startup** (`app.py`): On import, the Flask application loads `model.pkl`, `scaler.pkl`, and `features.pkl` from the same directory. If loading fails, the server still starts but returns 500 errors on `/predict` with `"Model not loaded"`.

3. **User Input** (`PredictionForm.js`): The user enters 12 biometric parameters through a styled form divided into four sections. BMI is calculated live as the user types height and weight.

4. **Form Submission** (`App.js`): Before sending to the API, the frontend inverts the `smoke` and `alco` values (swaps 0 ↔ 1). This is a workaround because the form labels "Smoking = ON" send `1`, but the training data encodes smoking as `1` for yes and the model was trained on the original encoding — the inversion aligns the UI with what the model expects.

5. **API Request** (`App.js` → `app.py:/predict`): A `POST` request with JSON containing all 12 features is sent to the Flask backend.

6. **Feature Extraction** (`app.py`): The server iterates over `feature_names` in order, extracts each value from the JSON body, provides fallback defaults for missing fields (e.g., `age_years` defaults to 50, `bmi` is computed from height/weight or defaults to 25).

7. **Prediction** (`app.py`): The feature vector is reshaped to a 2D array, scaled using `scaler.transform()`, and passed to `model.predict_proba()`. The probability of class 1 (disease) is extracted.

8. **Risk Categorization**: The probability is mapped to one of four categories: Low (<30%), Moderate (30–60%), High (60–80%), Very High (≥80%).

9. **Recommendations** (`app.py:get_recommendations`): A rule-based engine runs against the input data and predicted probability to generate a list of actionable health recommendations (e.g., "High cholesterol detected...", "Elevated blood pressure...", "Smoking increases cardiovascular risk...").

10. **Response** (JSON): The API returns the probability, risk category, prediction label, recommendations, and feature values.

11. **Result Display** (`App.js`): The frontend renders the risk percentage in a large, color-coded square, shows the risk category, displays recommendations, and provides risk metrics (confidence, severity).
